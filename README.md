# MacAuthAssistant · Mac 授权助手

独立的 macOS 菜单栏工具：识别系统管理员认证和部分无密码权限请求，倒计时后自动处理，支持历史记录和黑名单。纯 Swift / SwiftUI，使用 Apple 系统框架，无第三方运行依赖、服务端或其它工程依赖。

**自动处理会实际批准安装、系统修改或资源访问。** 请先检查倒计时和过滤规则，再开启自动处理。

## 功能

- 管理员凭据保存在本机钥匙串；自动填写并点击实际确认按钮。
- 支持 1–300 秒倒计时、取消本次、立即执行、独立暂停两类自动处理。
- 受控聚焦系统认证窗口；失焦时暂停，恢复后重新倒计时。
- 按明确请求语义和按钮标签处理普通系统权限，支持中英日识别规则。
- 最近 1000 条统一历史：待处理、已提交、成功、失败、忽略及原因。
- 从历史屏蔽同一请求，或组合类型、权限类别、正文关键词过滤；规则支持编辑、启停、删除。
- 原生登录项、后台启动和设置恢复，启动时不自动打开设置窗口。
- GitHub 发行说明、正式版/预览版、自动/手动检查更新、跳过版本、校验下载和安装重启。

## 环境与构建

需要 macOS 13 或更高版本，以及支持 Swift 5.9 或更高版本的 Xcode / Command Line Tools。开发与系统弹窗实测目前在 Apple Silicon、macOS 27.0.1 上完成，其它版本尚未逐项实测。

```bash
swift test
python3 -m unittest discover -s Tests/Scripts
bash build-app.sh --unsigned
```

产物位于 `dist/MacAuthAssistant.app`。`--unsigned` 只组装供审查的应用包，不应用开发者证书签名，不公证，也不适合作为依赖稳定辅助功能授权的正式安装版本。

实际安装使用自己钥匙串中有效的 Apple Development 或 Developer ID Application 证书，并固定签名身份：

```bash
security find-identity -v -p codesigning
MAC_AUTH_SIGNING_IDENTITY='<证书的 40 位 SHA-1>' bash build-app.sh
```

也可将证书 SHA-1 单独写入 `.signing-identity.local`，该文件不会进入 Git。构建不会静默回退到临时签名。更换签名身份可能需要重新授予辅助功能权限及钥匙串访问权限；升级时应沿用原身份。签名构建不等于完成 Apple 公证。

## 使用

1. 将签名后的完整应用包放入 `~/Applications` 或 `/Applications`。更新前退出旧进程，再替换完整应用包。
2. 启动后点击菜单栏锁形图标 →“设置…”。在系统设置 → 隐私与安全性 → 辅助功能中手动添加并开启该应用。
3. 保存管理员凭据、选择倒计时并主动开启管理员自动处理。首次默认关闭，保存新凭据也会暂停处理。
4. 无密码权限有独立开关。该功能默认开启；可在设置或菜单栏暂停，不依赖管理员密码。
5. 从菜单栏或设置页打开“历史记录与黑名单…”，查看原因或创建过滤规则。

设置窗口可以保持打开。正常启动仅在后台运行；“登录后自动启动”使用 macOS 原生登录项，系统要求批准时需要本人完成。已有凭据不能静默读取时，在设置页点击“读取已保存凭据”，按系统提示处理，不要删除原凭据后盲目重试。

## 记录与过滤规则

同一窗口反复扫描不会反复新增记录。成功表示助手提交后观察到窗口关闭，**不等于原软件的安装或业务任务成功**。失败不连续重试密码；中途退出导致结果未验证的记录标为忽略。

“屏蔽同一请求”根据规范化静态正文的 SHA-256 指纹匹配，正文变化会视作另一请求。自定义规则可按管理员/普通权限类型、权限类别及正文关键词过滤；单条规则内所有条件同时满足才匹配，多条规则任意一条命中即忽略。规则在自动聚焦、倒计时与提交前检查；已发送的确认不能通过事后加规则撤回。

历史与规则重启保留，清空历史保留规则。停用规则后，仍存在且符合原处理条件的窗口可以继续处理，旧忽略记录保留。旧权限诊断缺少任务标识的条目不能创建精确任务规则。

## 版本与更新

从菜单或设置打开“版本与更新…”，查看当前版本、构建号、源码修订、发行记录和说明。自动检查每天最多一次，只读取本仓库公开的 GitHub Release，不上传凭据或运行记录。支持正式/预览通道、手动检查、跳过版本及恢复提醒。

下载和“安装并重启”需要用户点击。安装前验证大小、SHA-256、应用标识、版本、系统要求和当前签名身份；退出后整体替换应用，保留旧包并在失败时尝试恢复。凭据、设置、历史和规则保留；无稳定签名的审查包不能自动安装。没有本机架构安装包、网络失败和暂无发行会明确区分。版本声明、打包及发布方法见[版本与发布](docs/releases.md)。

## 隐私与数据

凭据只保存在本机钥匙串，不进入源码、配置文件、剪贴板或日志。密码键盘事件只发送给重新核对的目标进程，不向全局键盘事件流发送。

偏好使用本机 UserDefaults；历史和诊断位于 `~/Library/Application Support/MacAuthAssistant/`，JSON 文件权限为 0600。历史包含应用名、简短任务说明、状态、时间、规则标识和正文指纹；不保存密码、账号输入框内容、完整正文或截图。任务说明可能包含应用或资源名称，报告问题时请自行脱敏。

历史/黑名单文件读取失败会保留原文件并暂停自动操作；保存失败会显示提示，不代表已保存。运行数据不作为工程内容提交。

## 兼容范围与验证状态

只接受经实际 Apple 签名验证的系统提供方。管理员处理拒绝多个密码框、已有人工输入、不支持操作接口及独立凭据表单；每个窗口只尝试一次。目标或焦点变化时停止。

普通权限目前扫描系统 UserNotificationCenter，按明确语义识别文件夹、本地网络、相机、麦克风、屏幕、定位、通讯录、通知、照片、日历、蓝牙、应用间控制。未知窗口、网页、支付/删除/软件安全警告、密码管理器授权及 AI 工具自身的访问授权不自动处理。需进入系统设置批准的权限由本人操作。

Apple Account、网络账户、独立钥匙串/磁盘密码、修改密码、FileVault 开机认证和锁屏登录不在通用管理员凭据填写范围内。系统接口变化可能需要适配，不能保证覆盖所有 macOS 版本和弹窗。

0.1.12 的原有 63 项行为回归与新增更新回归一起维护；当前版本声明以 `Version.json` 为准。真实管理员自检、某第三方应用的管理员授权及自动聚焦、本地网络权限自动允许已在本机验证；通知测试没有出现真实提示，不能算通过。其它普通权限类别仍以规则回归为主。历史/黑名单有持久化、去重、过滤与异常保护测试，但真实弹窗命中黑名单和停用后恢复尚未完成完整实机验收。

在设置中点击“使用已保存凭据验证真实管理员弹窗”可发起一次系统身份自检；不执行特权命令、安装或系统设置写入。缓存授权、人工干预、阶段不完整或系统失败均不算完整自动通过。测试前请保存正在进行的工作，不要将窗口关闭直接当作授权成功。

参见 [贡献指南](CONTRIBUTING.md) 和 [架构说明](docs/design.md)。测试用钥匙串服务和偏好域使用独立标识；`Tests/Fixtures` 仅用于手动集成验收，不包含在正式应用包中。CI 运行行为测试及无证书构建，不能替代真实系统弹窗验收。
